## Dataset

The two committed synthetic fixtures total 49 lines and 980 bytes: an 18-line,
361-byte `pyproject.toml` with 12 exact direct requirements, and a 31-line,
619-byte GitHub Actions workflow with 6 tagged Actions. The compact dataset
isolates upstream release discovery and update-writing costs from repository
traversal.

## Python manifest constraints

Both tools checked the same twelve exact direct requirements. For the update
operation, Hyperfine restored the original `pyproject.toml` before every run;
both tools raised all twelve pins and left valid TOML.

| Operation | Tool | Mean ± standard deviation | Range |
|---|---|---:|---:|
| Check | upd | 263.1 ± 96.6 ms | 137.0–350.1 ms |
| Check | uppd | 407.8 ± 174.7 ms | 287.1–709.9 ms |
| Update | upd | 330.2 ± 229.1 ms | 143.0–716.7 ms |
| Update | uppd | 360.2 ± 60.9 ms | 281.2–422.8 ms |

Commands:

```bash
# check
upd --no-cache --format json --lang python <pyproject.toml>
(cd <fixture-directory> && uppd --dry-run)

# update
upd --apply --no-cache --format json --lang python <pyproject.toml>
(cd <fixture-directory> && uppd)
```

Commands:

```bash
# check

actions-up --json --min-age 0 --dir <fixture-directory>/.github
(cd <fixture-directory> && taze major --force --json)
(cd <fixture-directory> && ratchet upgrade -out <temporary-output> .github/workflows/ci.yml)

# update
upd --apply --no-cache --format json --lang actions <fixture-directory>
pinact run --update <workflow>
actions-up --yes --min-age 0 --dir <fixture-directory>/.github
(cd <fixture-directory> && taze major --force --write)
(cd <fixture-directory> && ratchet upgrade .github/workflows/ci.yml)
```

## Interpretation and limits

- The Python fixture is deliberately a manifest-editing workload. It excludes
  uv/PDM resolution and environment installation.
- GitHub measurements include live DNS, TLS, API, release/tag selection, and
  output generation. Server-side variance is visible in the ranges.
- `upd --no-cache` and `taze --force` bypass their persistent result caches.
  The other tested commands expose no equivalent documented cache switch.
- Check commands have different success exit conventions. Hyperfine's
  command wrappers assert the expected status because `upd` and pinact return
  `1` when they find pending work. Any error status aborts the benchmark.
- Hyperfine emitted platform-specific memory samples, but identical values were
  observed across unrelated child processes on this macOS run. They are not
  published as comparable peak-memory measurements.
- Five runs are enough for a basic project snapshot, not for a scientific claim.
  Use the raw data and repeat the harness in the target deployment environment
  before making a performance-sensitive tool choice.
