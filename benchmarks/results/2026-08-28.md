## Output verification

Before timing, the harness ran each update command once and inspected its
result. Both Python tools raised all 12 exact constraints and produced parseable
TOML. Every Actions tool changed all 6 references while retaining all 6 workflow
steps. The transcript is committed as
[`2026-08-28-verification.txt`](2026-08-28-verification.txt).

`uppd` 1.6.0 appended an extra closing bracket when overwriting this fixture in
place on the recorded environment. Its timed update therefore uses the tool's
documented `--outfile updated.toml` mode, which passed the same parse and
12-change checks as `upd`. This avoids reporting a fast but malformed result.

## Dataset

The two committed synthetic fixtures total 49 lines and 980 bytes: an 18-line,
361-byte `pyproject.toml` with 12 exact direct requirements, and a 31-line,
619-byte GitHub Actions workflow with 6 tagged Actions. The compact dataset
isolates upstream release discovery and update-writing costs from repository
traversal.

## Python manifest constraints

Both tools checked the same twelve exact direct requirements. For the update
operation, Hyperfine restored the original `pyproject.toml` before every run.
`upd` updated that copy in place; `uppd` wrote a separate verified result.

| Operation | Tool | Mean ± standard deviation | Range |
|---|---|---:|---:|
| Check | **upd** | **134.7 ± 10.0 ms** | 124.9–147.1 ms |
| Check | uppd | 269.7 ± 22.7 ms | 244.4–297.3 ms |
| Update | **upd** | **138.7 ± 3.5 ms** | 134.4–143.5 ms |
| Update | uppd | 250.8 ± 12.8 ms | 243.1–273.3 ms |

Commands:

```bash
# check
upd --no-cache --format json --lang python <pyproject.toml>
(cd <fixture-directory> && uppd --dry-run)

# update
upd --apply --no-cache --format json --lang python <pyproject.toml>
(cd <fixture-directory> && uppd --outfile updated.toml)
```

In this run, `upd` recorded a 50% lower check mean and a 45% lower update mean
than `uppd`. Those percentages describe this fixture, environment, and five-run
sample only.

Commands:

```bash
# check

(cd <fixture-directory> && taze major --force --json)
(cd <fixture-directory> && ratchet upgrade -out <temporary-output> .github/workflows/ci.yml)

# update
upd --apply --no-cache --format json --lang actions <fixture-directory>
pinact run -update <workflow>
actions-up --yes --min-age 0 --dir <fixture-directory>/.github
(cd <fixture-directory> && taze major --force --write)
(cd <fixture-directory> && ratchet upgrade .github/workflows/ci.yml)
```

`upd` recorded the lowest check mean in this run. Taze recorded the lowest
update mean; `upd` was second. The tag-preserving tools do less output-policy
work than the three SHA-pinning tools, so latency is only one selection factor.

## Interpretation and limits

- The Python fixture is deliberately a manifest-editing workload. It excludes
  uv/PDM resolution and environment installation.
- GitHub measurements include live DNS, TLS, API, release/tag selection, and
  output generation. Server-side variance is visible in the ranges.
- `upd --no-cache` and `taze --force` bypass their persistent result caches.
  The other tested commands expose no equivalent documented cache switch.
- Check commands have different success exit conventions. Hyperfine's command
  wrappers assert the expected status; any unexpected success or error aborts
  the benchmark instead of measuring an error path.
- Five runs are enough for a basic project snapshot, not a scientific claim.
  Repeat the harness in the target environment before making a
  performance-sensitive tool choice.
